# Анализ двух нагрузочных прогонов

Источник: 10vus-30s.json и 50vus-10s.json; необработанный вывод k6 сохранён рядом. Оба запуска завершились с кодом 0, все установленные пороги выполнены.

| Показатель | 10 VUs, 30 с | 50 VUs, 10 с |
|---|---:|---:|
| Запросов | 5161 | 8066 |
| Запросов в секунду | 171.72 | 801.93 |
| Среднее время ответа, мс | 6.773 | 10.610 |
| p95 времени ответа, мс | 8.089 | 26.408 |
| Максимальное время ответа, мс | 22.875 | 81.665 |
| Ошибки HTTP, % | 0 | 0 |
| Неуспешные проверки ответа | 0 | 0 |

При увеличении числа пользователей в 5 раз частота запросов выросла примерно в 4.67 раза. p95 увеличился примерно в 3.26 раза и остался ниже выбранного порога 500 мс. Проверки статуса и JSON прошли для всех ответов; ошибок HTTP не зарегистрировано.

Сравнение отражает поведение данного локального стенда при этих параметрах, а не максимально возможную производительность. Число запросов нельзя сравнивать без учёта длительности. Пауза между запросами - 50 мс; endpoint содержит задержку 5 мс. Генератор и сервер работают на одном компьютере, фоновые процессы не изолировались.
